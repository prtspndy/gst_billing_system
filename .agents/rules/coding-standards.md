# Coding Standards

This document defines the coding standards and development practices for this Flutter + GetX project.

Follow these rules strictly when creating, modifying, refactoring, or debugging code.

---

## 1. General Code Quality

- Write clean, readable, maintainable, and production-quality code.
- Follow official Dart and Flutter best practices.
- Use meaningful names for variables, functions, classes, methods, files, and folders.
- Keep code simple and easy to understand.
- Prefer straightforward solutions over clever or complicated solutions.
- Avoid unnecessary complexity.
- Keep files focused on a clear responsibility.
- Keep methods and classes reasonably small.
- Do not duplicate code.
- Do not write code only to make a feature appear complete.
- Implement functionality correctly rather than superficially.

---

## 2. Clean Code Principles

Follow these principles:

- Clean Code
- DRY
- KISS
- YAGNI
- SOLID
- Separation of Concerns
- Reusability
- Maintainability
